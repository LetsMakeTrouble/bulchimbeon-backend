### M-1을 맨 앞에 두는 이유

임계값 세트(80/50/0.92/0.85)는 `ada-002` 시대(평균 코사인 ≈0.85) 캘리브레이션이다. `text-embedding-3-small`은 평균 ≈0.43이므로 **리스케일 파라미터를 실측 없이 두면 🟢이 한 건도 나오지 않는다.** 이 결함은 `FakeLLMProvider`의 해시 기반 벡터로는 원리적으로 검출되지 않으므로(`06 §5`), **테스트가 전부 초록인 채로 데모 당일에 발견된다.** 15분의 프로브가 그 시나리오를 막는다.

> ✅ **M-1 실측(2026-08-07)이 이 예측을 확인했다.** 원시 스케일에서 🟢 대역 9건 중 **S≥80이 0건**이었다(최대 Q6 72). 리스케일 도입이 확정됐다.
> 더불어 **예측하지 못했던 결함 두 개**가 추가로 드러났다:
> 1. **시드 검색 실패** — Q3("지원하는 통화가 뭐예요?")가 `Sandbox` 청크를 top-1로 잡았다. `currency`가 5개 필드를 나열하는 다목적 청크에 묻혀 있었기 때문. 결정 1.7에 따라 임계값이 아니라 시드를 보강했다(`08 §2`에 `Currencies` 청크 신설, 21→22청크).
> 2. **부분 UNIQUE 단일 UPDATE의 행 순서 의존성** — 문서는 "23505로 실패한다"를 전제했으나 실제로는 **절반이 통과**한다(`04 §7`). 항상 실패하는 것보다 위험하다.
>
> 둘 다 `FakeLLMProvider`로는 검출 불가능한 부류이며, M3 이후에 발견됐다면 파이프라인 테스트를 다시 썼어야 했다.
> 실제 소요는 15분 예상보다 길었다(재실행 1회 + 손 조정 + 지연 분포 n=8 + SQL 프로브 확장).

M-1 산출 표(유사도 분포 · 지연 실측)는 그대로 발표 자료로 재사용한다.

## 컷라인 (시간 부족 시 포기 순서)

기준선은 **데모 스크립트 1~6단계**(`08 §4`)다. 아래 순서대로 버린다.

1. **M8 외부 연동 전부** — 이제 컷라인이 아니라 **기본 제외**다. `POST /integrations` 스텁 + **501**만 남기고 "확장 포인트"로 발표한다(기획서 예상질문 대비 문구 유지).
2. **교훈 메모리(M6 후반)** — 데모에 등장하지 않는다. 테이블 + 조회 API만 남기고 추출·승인 루프는 버린다.
3. **알림 다국어 문안** — 한국어 고정. **`answer.corrected`만 양쪽 언어**로 남긴다(룰 8의 시연 지점).
4. **브리핑 스케줄러** → `GET /briefing/today` 수동 조회만. ⚠️ **이때 M5의 `notifications.deliver_after` 보류 로직도 함께 컷**한다 — 보류만 하고 flush할 스케줄러가 없으면 알림이 영원히 안 오는 반쪽 상태가 된다.
5. **M2 DOCX·PDF** → MD/TXT만 (시드 데이터가 MD이므로 데모 무영향).
6. **M7 지표** → `auto_answer_rate` + `saved_wait_hours` **2종만**.

- **절대 컷 불가**: **M-1**, **M3**, **M4** + M5의 SSE `answer.completed` + M9 시드.
  - M-1은 15분이고, 빠뜨리면 M3의 결과물이 통째로 무의미해진다.
  - M3·M4는 신뢰등급 분기 + 답이 없을 때 시작되는 워크플로 = 차별점 그 자체다.

## ⚠️ 작업량 현실 경고 (읽고 시작할 것)

- 계약서 기준 **엔드포인트 55개 이상 · 테이블 18개**다(수치 원천: `05` 메서드 표 행 수 + §8·§13·§14 헤딩형, `04 §2` 테이블 헤딩 수). 스캐폴딩·테스트·디버깅을 포함한 실작업은 **96~153시간**으로 추정된다.
- 7일 환산 시 **하루 14~22시간**. **컷라인을 적용하지 않으면 완주는 불가능하다.** 위 컷라인은 "여유 있으면 참고"가 아니라 **기본 실행 계획**으로 읽어야 한다.
- **병목은 M3이 아니다.** M3은 범위가 명확하고 테스트가 판정해 준다. 실제 병목은 **M5 + M6를 동시에 처리하는 6~7일차 구간**이다 — 알림·SSE·스케줄러·브리핑·교훈이 서로 얽혀 있고 DoD가 통합 시나리오라 부분 완성이 안 된다. 여기서 막히면 컷라인 2·3·4번을 **주저 없이** 실행한다.
- 6일차의 클라우드 배포가 늦어지면 그 자체가 신호다. 배포가 하루를 먹으면 M6 이후는 컷 대상이다.

## 진행 규칙

- 프롬프트 1개 = Claude Code 세션 1개 권장 (컨텍스트 집중). 완료 후 커밋: `feat(M3): question pipeline with grading`.
- 각 세션 시작 시 CLAUDE.md가 자동 로드되고, 프롬프트 안의 `@docs/...` 참조가 해당 설계 문서를 로드한다.
- DoD의 테스트가 깨진 채로 다음 마일스톤 프롬프트를 시작하지 않는다.
- **M-1의 산출값을 `config.py`의 `DEFAULT_SETTINGS` 한 곳에만** 반영한다. 다른 파일에 임계값을 복사하지 않는다(룰 1).
- 프론트 팀 공유 시점: M1 끝나면 `05-api-contract.md` + Swagger URL 1차 공유 → M4 끝나면 최종 확정 공지.
