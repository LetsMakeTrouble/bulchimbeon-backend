# 답변 파이프라인

## 파이프라인 일곱 단계
질문 하나가 들어오면 일곱 단계를 지난다. ① 한국어 질문을 영어로 번역한다. ② 확정된 공식
Q&A 중 같은 질문이 있는지 본다. ③ 프로젝트 경계 안의 활성 문서 청크를 벡터로 검색한다.
④ 검색된 근거만으로 답변 초안을 만든다. ⑤ 만든 문장마다 근거가 실제로 있는지 검증한다.
⑥ 매칭률을 계산해 등급을 매긴다. ⑦ 담당자에게 넘길 확인 카드를 구조화한다. 번역을 ①에
두는 이유는 지식 문서와 질문의 언어가 다르기 때문이다. 검색 축이 영어로 통일되어야
문서가 영어로 쓰여 있어도 한국어 질문이 같은 벡터 공간에서 걸린다.

## 매칭률 계산
매칭률은 검색 점수 S 와 근거 충족도 G 의 **최솟값**이다. 평균이 아니다. 둘 중 하나라도
낮으면 답변을 믿을 수 없다고 보기 때문이다. S 는 top-1 청크의 원시 코사인 유사도를
`s_floor` 와 `s_ceil` 사이에서 0~100 으로 다시 스케일한 값이다. G 는 생성된 문장 중 근거가
붙은 문장의 비율이며, 분모는 **생성 시점의 원본 문장 수로 고정**한다. 근거 없는 문장을
잘라내도 분모는 줄지 않으므로 프루닝으로 매칭률을 끌어올릴 수 없다.

## 등급 분기
매칭률이 `green_threshold` 이상이면 즉답으로 발행한다. `yellow_threshold` 이상
`green_threshold` 미만이면 답을 주되 담당자 확인 대기 표시를 붙인다. `yellow_threshold`
미만이면 질문자에게 발행하지 않고 담당자에게 넘긴다. 초안은 어느 등급이든 `draft` 로
시작하며 자동으로 확정되는 경로는 없다. 초록 답변도 확인 카드를 만들지만 브리핑과 알림
대상에서는 빠진다.

## 강제 보류 네 가지
점수와 무관하게 무조건 보류로 떨어뜨리는 조건이 넷 있다. 근거끼리 서로 다른 값을 말하는
`conflict`, 검색 top-1 유사도가 `similarity_floor` 미만이라 근거가 아예 없는
`no_evidence`, 모델 출력이 스키마를 만족하지 못한 `schema_failed`, 프로젝트의 일일 LLM
호출 상한을 넘긴 `quota_exceeded` 다. 이 넷은 방해금지 시간대에도 등급을 낮추지 않고
보류를 유지한다. 시간대 때문에 위험한 답변이 가려지면 안 되기 때문이다.

## 재사용 판정
②에서 질문의 영어 번역문 임베딩과 공식 Q&A 의 코사인이 `reuse_threshold` 이상이면
파이프라인을 더 돌리지 않고 확정된 답을 그대로 돌려준다. 이때 **한국어 원문을 다시
번역하지 않는다.** 확정 당시의 문장을 그대로 쓰는 것이 요지이며, 재번역하면 담당자가
승인한 문장이 매번 미세하게 달라진다. 재사용 답변만 `verified` 로 시작하고 확인 카드를
만들지 않는다. `similar_threshold` 이상 `reuse_threshold` 미만이면 재사용하지 않고
"비슷한 확정 답변"으로 화면에 첨부만 한다.

## 근거 인용과 스니펫
④가 만든 문장은 각각 어느 청크에서 나왔는지 연결된다. ⑤ 검증에 넘기는 청크는 **자르지
않고 전문을 넘긴다.** 화면 하이라이트용 스니펫 길이 제한은 표시 단계에서만 적용한다.
검증에 잘린 청크를 넘기면 생성은 전문을 보고 쓰고 검증은 앞부분만 보고 판정해 근거
충족도가 0 으로 무너진다.
