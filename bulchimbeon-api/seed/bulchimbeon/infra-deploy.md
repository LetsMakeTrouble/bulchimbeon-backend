# 배포 구성

## 컨테이너 구성
배포는 네 개의 서비스로 이루어진다. `db` 는 pgvector 확장을 올린 PostgreSQL 18 이고 호스트
포트를 열지 않는다. `migrate` 는 마이그레이션을 끝까지 올리고 종료하는 일회성 컨테이너이며,
여기서 실패하면 `api` 는 시작하지 않는다. 마이그레이션 실패가 앱 재시작 루프에 묻혀 원인이
가려지는 것을 막기 위해서다. `api` 는 FastAPI 이고 모든 경로가 `/api/v1` 아래에 있다.
`web` 은 프론트 정적 번들을 nginx 로 서빙한다. API 는 워커 하나로 고정한다. SSE 구독자 큐가
프로세스 메모리에 있고 스케줄러가 프로세스마다 중복 발화하기 때문이다.

## 앞단 라우팅
공개 도메인은 Cloudflare Tunnel 이 받는다. 터널이 `/api/` 로 시작하는 경로는 API 컨테이너의
8000 포트로, 나머지는 웹 컨테이너의 8080 포트로 보낸다. 브라우저 입장에서 프론트와 API 가
같은 오리진이므로 교차 출처 요청이 아니다. 프론트 nginx 에는 API 프록시 블록을 두지 않는다.
한 번 더 프록시하면 홉이 늘고 버퍼링과 타임아웃 설정이 두 군데로 갈리는데, 스트리밍 응답은
버퍼링 하나만 어긋나도 오류 없이 조용히 멈춘다. 라우팅 규칙이 빠지면 로그인 요청이 정적
서버에 닿아 405 를 받고, 화면에는 비밀번호 오류처럼 보인다.

## 환경변수와 빌드
프론트의 API 주소는 빌드 시각에 번들로 박히므로 값을 바꾸면 이미지를 다시 구워야 한다.
런타임 재시작으로는 반영되지 않는다. 연동 토큰을 암호화하는 키는 바뀌면 저장된 토큰을
복호화할 수 없어 연동을 전부 다시 등록해야 하므로 한 번 정하면 유지한다. 데이터베이스
비밀번호는 데이터 볼륨이 처음 만들어질 때만 적용된다. 볼륨이 이미 있으면 초기화를 건너뛰므로
환경 파일만 바꿔도 데이터베이스 안의 비밀번호는 예전 값 그대로 남는다.

## 데이터와 백업
백업은 두 가지를 함께 받아야 한다. 데이터베이스 볼륨에는 질문과 답변과 청크와 임베딩이
들어 있고, 스토리지 볼륨에는 업로드된 원본 파일이 들어 있다. 데이터베이스만 백업하면 청크는
남지만 원문이 복구되지 않아 문서를 다시 인제스트할 수도 없다. 데모 데이터는 시드 스크립트가
넣으며, 배포 스크립트는 시드를 돌리지 않는다. 시드는 프로젝트와 문서를 넣는 기본 실행과
질문 이력까지 채우는 실행으로 나뉘고, 이력 실행은 실제 모델을 호출하므로 비용과 시간이 든다.
